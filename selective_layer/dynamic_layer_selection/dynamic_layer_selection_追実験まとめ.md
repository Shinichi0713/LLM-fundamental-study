## 1. 背景：論文は何を言いたいのか

### 1.1 問題意識

GPT 系の **decoder-only Transformer** は、同じ構造のデコーダ層を何十個も縦に積んでいます（OPT-1.3B なら **24層**）。推論時は入力がすべての層を通るため、層数に比例して計算量がかかります。

そこで発想が生まれます。

> **「全部の層を通さなくても、足りる層だけ通せばいいのではないか？」**

ただし、ここで2つの疑問がぶつかります。

- どの層を飛ばすか（構成の問題）
- 入力（プロンプト）ごとに必要な深さは違うのではないか（制御の問題）

論文の **Section 3.3** と **Appendix A.5** は、後者の「序列（プロンプト）単位で深さを選べたら、理論的にどれだけ得か」を調べた実験です。

### 1.2 Uniform Layer Skipping（ULS）

まず「層を飛ばす」方法を統一します。論文の式(2)に従い、**深さ方向に均等に層を残します**。

- 1層目は必ず残す
- 残す层数を `c` とすると、`c = 4, 8, 12, 24` の4構成を用意
- `c = 24` は何も飛ばさない**フルモデル**

例えば 24層から `c=4` なら、おおよそ 1, 7, 13, 19 層目あたりが残ります（実際の選択は §4.2 の式(2)の計算で決まります）。

> **用語**: `c` = 「その推論で実行する层数」＝コスト。論文ではこれを予算 β と比較します。

### 1.3 オラクル（Oracle）という「上限」

ここがこの実験の肝です。

**オラクル**とは、各プロンプトについて「どの深さでどれだけ良い答えが出るか」を**テストの正解スコアを見て知っている**仮想の制御器です。

- 制約: 全プロンプトの**平均コスト ≤ β**
- 目的: 平均スコア（ROUGE-L）を最大化
- 解法: **多選択ナップサック問題**を動的計画法（DP）で解く

「各プロンプトにちょうど1つの深さを選ぶ」「合計コストが予算以内」「価値（スコア）を最大化」という形が、まさにナップサックです。

> ⚠️ **重要な注意**
> オラクルは**テスト用の正解 ROUGE を使って選ぶ**ので、実用できる制御器ではありません。論文自身も Appendix A.5.1 で「sampling advantage（出力のノイズまで事後的に利用している）」を認め、ベイズ最適を超えていると述べています。
> つまり **「オラクルの数字＝達成可能な性能」ではなく「理論上の上限」** です。この記事でもその前提で読みます。

### 1.4 論文の主結果（比較の基準）

| 項目                 | 論文中の数字                                               |
| -------------------- | ---------------------------------------------------------- |
| モデル               | OPT-1.3B（24層）を Alpaca で 6エポック**フル微調整** |
| 評価データ           | Alpaca 7,800件                                             |
| フルモデルの ROUGE-L | **0.342**                                            |
| 静的 c=4 の ROUGE-L  | **0.249**（フル比 ≈ 0.73）                          |
| フルに並ぶ最小コスト | **平均 5.6 層（23.3%）**                             |
| そのときの選択比率   | **c=4 が 69.6%**                                     |

「23%の層でフルと同等」——この数字を Colab でどこまで追えるかが実験の出発点です。

## 2. 実験の内容：何をしたのか

ノートブックは2つのパートに分かれています。

### Part A（§1〜6）：微調整なしの素のモデル

1. `facebook/opt-iml-1.3b` を読み込む（fp16 で約 2.6GB、T4 に載る）
2. Alpaca から評価用 **500件** を抽出（論文は 7,800件）
3. 4つの深さ `c = 4, 8, 12, 24` で greedy 生成
4. 各 (プロンプト, 深さ) の組み合わせで **ROUGE-L** を計算 → スコア行列 `R` を作る
5. `R` に対して、オラクル／greedy オラクル／random mix／学習ルーターを比較

### Part B（§7〜8）：スキップ状態のまま LoRA 微調整

1. 各 `c` ごとに**別の LoRA アダプタ**を用意（`c=24` のフルモデルにも同条件で適用）
2. その層構成のまま、Alpaca **2,000件・1エポック**で学習
   - 損失は**応答部分のみ**（プロンプトは `-100` でマスク）
3. 学習後に4モデルで再生成し、Part A と同じ分析を実行
4. フルモデル比で正規化した曲線を並べ、**微調整前後を比較**

> **試行錯誤の痕跡**
>
> - 最初に「オラクルのみの最小版」と「ルーター学習込みの版」のどちらにするか検討 → v2 ではルーター込みに
> - この作業環境には `torch` / `peft` が無いため、LoRA セルは**構文チェックのみ**、数値処理は**合成データで検証**
> - Colab 実行時に peft のバージョン差で `get_peft_model` / `set_adapter` 周りが壊れるリスクを事前に関注
> - `v1 → v2` で分析を `analyze_oracle` / `analyze_router` に関数化し、微調整前後の再利用を可能にした

## 3. 確認したい点：問いを整理する

実験で見たいのは、次の4つです。

| #            | 問い                                                         | 対応する指標                           | なぜ重要か                             |
| ------------ | ------------------------------------------------------------ | -------------------------------------- | -------------------------------------- |
| **Q1** | オラクルはどこまで層を削れるか？                             | フルに並ぶ最小 β                      | 論文の 5.6 層（23.3%）に近づくか       |
| **Q2** | 「予算配分の効果」と「出力ノイズの利用」は切り分けられるか？ | oracle vs greedy vs random mix vs 静的 | オラクルの数字の信頼性を担保する       |
| **Q3** | 微調整すれば深く削ったモデル（c=4）が立ち上がるか？          | 静的 c=4 のフル比／選択比率            | 論文で c=4 が 69.6% 選ばれた理由の検証 |
| **Q4** | プロンプトだけから深さを予測できるか？                       | ルーター vs random mix の差            | **実用化の見込み**そのもの       |

特に Q2 が重要です。オラクルが静的モデルを上回っても、それが「良い配分をしたから」なのか「たまたま良い出力を事後的に拾っただけ」なのかを分ける必要があります。

- **greedy oracle**: 各プロンプトで `c ≤ β` のうち最良を選ぶだけ。予算の融通はしない。→ ここに sampling advantage が残る
- **oracle**: 予算をプロンプト間で融通する。→ sampling advantage ＋ 配分効果
- 両者の差が**予算配分そのものの効果**の目安になります

## 4. 実装の方法：ノートブックの構成

### 4.1 設定（§0, Cell 2）

```python
CFG = dict(
    model_name="facebook/opt-iml-1.3b",
    n_samples=500,            # 評価プロンプト数（論文は 7800）
    max_prompt_tokens=256,
    max_new_tokens=128,
    batch_size=16,
    costs=[4, 8, 12, 24],
    seed=0,
    out_dir="/content/seq_oracle",   # キャッシュ先（Drive 推奨）
    n_train=2000,             # LoRA 学習件数
    ft_epochs=1, ft_lr=2e-4, ft_batch=8, ft_accum=2,
    lora_r=16,
)
```

データ分割は、評価用を末尾 15%、学習用を先頭 70% から取ることで**重複を防いで**います（§1）。

### 4.2 均等レイヤスキップ（§2, Cell 7）

論文式(2)をそのまま実装しています。

```python
def uniform_pattern(L, c):
    U = [1]
    for l in range(2, L + 1):
        U.append(1 if sum(U) <= (l - 1) * c / L + 1e-9 else 0)
    return U
```

**実装の肝は `skip_layers` コンテキストマネージャ**です。

```python
@contextmanager
def skip_layers(model, c):
    dec = model.model.decoder
    orig_layers = dec.layers
    keep = [i for i, g in enumerate(uniform_pattern(len(orig_layers), c)) if g]

    # KV キャッシュの添字ずれを避けるため layer_idx を振り直す
    saved = [(l.self_attn, getattr(l.self_attn, "layer_idx", None)) for l in orig_layers]
    for pos, i in enumerate(keep):
        orig_layers[i].self_attn.layer_idx = pos

    dec.layers = torch.nn.ModuleList([orig_layers[i] for i in keep])
    model.config.num_hidden_layers = len(keep)
    try:
        yield
    finally:
        dec.layers = orig_layers                       # 必ず元に戻す
        model.config.num_hidden_layers = orig_n
        for attn, idx_ in saved:
            attn.layer_idx = idx_
```

> **初心者へのポイント**: 層を抜くだけだと、Attention が「自分は何層目か」を表す `layer_idx` の番号が飛んでしまい、KV キャッシュの対応が壊れます。**残した層に 0,1,2… と振り直す**のが実務上の必須テクです。Cell 9 で `c=24 が素のモデルと一致する` ことを確認してから本体に進みます。

### 4.3 生成と ROUGE-L（§3, Cell 11）

- プロンプトを**長さ順に並べて**パディングを削減
- 生成結果は `gens{tag}_c{c}_n{len(prompts)}.json` にキャッシュ（再実行時に再利用）
- `rouge_score` の `rougeL.fmeasure` を (プロンプト × 深さ) の行列 `R` に格納

> ROUGE-L とは、生成文と正解文の**最長共通部分列（LCS）**を見て一致度を測る指標です。0〜1 で、大きいほど正解に近いという意味です（翻訳・要約の評価で定番）。

### 4.4 オラクルの DP（§4, Cell 13）

多選択ナップサックを解きます。効率化のため、コストを最大公約数で割って整数化しています。

```python
g = reduce(gcd, costs)          # costs=[4,8,12,24] → g=4
u = [c // g for c in costs]     # → [1, 2, 3, 6]
```

`prev[w]` を「コスト `w` 以下で得られる最大スコア」として、プロンプトを1つずつ畳み込みます。最後に予算 β から割当てを逆再生します。

比較対象は3つ。

| 手法                    | 定義                                    | 何が分かるか                         |
| ----------------------- | --------------------------------------- | ------------------------------------ |
| **oracle**        | DP で平均コスト ≤ β の下で最適化      | 理論上限（配分＋ノイズ利用）         |
| **greedy oracle** | 各系列で `c ≤ β` の最良を選ぶだけ   | sampling advantage の近似            |
| **random mix**    | oracle と同じ選択比率をランダムに割当て | 配分ではなく**比率だけ**の効果 |

### 4.5 学習ルーター（§6, Cell 17）

「実用化」を問うパートです。

- 特徴量: OPT の**第12層の隠れ状態を attention mask で平均プーリング** ＋ プロンプト長の log
- 各深さの ROUGE-L を **Ridge 回帰**で予測（5分割 CV）
- 「予測スコアが c=24 より `τ` 以内に収まる最安の深さ」を選択
- `τ` を動かしてコスト→精度の曲線を描く

> ルーター自体の計算コスト（プロンプト1回分の前向き計算）は**数えていません**。この点も解釈に注意が必要です。

### 4.6 LoRA 微調整（§7, Cell 19〜20）

- `target_modules=["q_proj","k_proj","v_proj","out_proj","fc1","fc2"]`
- `r=16`, `alpha=32`, `dropout=0.05`
- `get_peft_model` で `c4` アダプタを作り、残りを `add_adapter` で追加
- **肝**: `with skip_layers(base, c)` の中で学習する＝「削った構成のまま」勾配を流す
- `GradScaler` ＋ `autocast("cuda", float16)` で fp16 学習
- アダプタは `lora_c{c}_n{2000}_e{1}.pt` に保存

> ⚠️ **実行順序の罠**: `get_peft_model` は `model` に **in-place** で LoRA を注入します。Part B を実行した後に同じセッションで §2〜§6 を再実行すると、微調整なしの結果が汚れます。ノートブックの冒頭にも警告が書かれています。

## 5. 実験の結果：何が出たのか

以下は `result_sequence.md` に報告された数値です（ノートブック側には出力が保存されていないため、実行後に報告されたものを転記しています）。

### 5.1 微調整の効果（静的モデルの ROUGE-L）

| 指標              |        微調整前 |                  微調整後 |           論文 |
| ----------------- | --------------: | ------------------------: | -------------: |
| フルモデル (c=24) |           0.232 |           **0.312** |          0.342 |
| フルに並ぶ最小 β | 17.0 層 (70.8%) | **11.5 層 (47.9%)** | 5.6 層 (23.3%) |

- フルモデルのスコアは 0.232 → 0.312 と大きく上がり、**論文の 0.342 にかなり近づきました**。基準モデルとしては概ね妥当な水準です。
- オラクルがフルに並ぶ最小 β も 70.8% → 47.9% と下がりました。**しかし論文の 23.3% の約2倍**です。

### 5.2 β=8 の内訳（報告された値）

| 手法             |         ROUGE-L |             静的 c=8 との差 |
| ---------------- | --------------: | --------------------------: |
| 静的 c=8         |           0.182 |                          — |
| greedy oracle    |           0.184 |                      +0.002 |
| random mix       |           0.143 |                     −0.039 |
| **oracle** | **0.257** | **+0.075（約4割増）** |

ここから3つのことが読み取れます。

1. **sampling advantage は小さい**: greedy (0.184) と静的 c=8 (0.182) はほぼ同じ。
   → 「複数モデルから良い出力を拾っただけ」では説明がつきません。
2. **予算配分の効果は大きい**: oracle は静的より +0.075、random mix より +0.114。
   → 系列ごとの「適材適所」が効いています。
3. **混合そのものは損**: random mix が静的 c=8 を下回りました。
   → 深さと品質の関係が**上に凸**（c=4→8 で大きく伸び、その先は伸びが鈍る）ため、平均すると損になります。この不利を払っても oracle が上回っているので、配分効果は本物に見えます。

### 5.3 選択比率（再現できなかった部分）

| 項目                          |            論文 |            今回 |
| ----------------------------- | --------------: | --------------: |
| フルに並ぶ β での c=4 選択率 | **69.6%** | **11.4%** |

論文では「浅いモデルを大部分使う」絵になっていましたが、今回は c=4 がほとんど選ばれませんでした。

**推測される原因**: c=4 モデルの品質が回復しきれていないこと。論文はフル微調整・全量・6エポックですが、今回は **LoRA・2,000件・1エポック**です。深く削った構成を立て直すには、容量（rank）も学習量も足りなかった可能性があります。

> この仮説を確認するには、**微調整後の静的 c=4 と c=12 の ROUGE-L** が必要です（論文では c=4 がフルの約 0.73 倍）。ログではここが「教えてほしい」と返されており、**まだ確認されていません**。

### 5.4 学習ルーター

予測と実測の相関（c=4, 8, 12, 24 の順）:

| 深さ | 微調整前 |        微調整後 |
| ---- | -------: | --------------: |
| c=4  |    0.311 |           0.108 |
| c=8  |    0.140 | **0.342** |
| c=12 |    0.179 | **0.391** |
| c=24 |    0.363 |           0.340 |

c=8 と c=12 は改善しましたが、c=4 は低下しました。

> **初心者への注意**: ルーターに効くのは「各モデルの水準」ではなく「**モデル間の差**」（例: c=24 と c=8 の差）です。水準の予測が当たっても、差の予測が当たらないことは十分ありえます。したがって実用化の見込みは、**ルーターと random mix の曲線の差**で判断するのが正解です。この差も、ログではまだ提示されていません。

## 6. 結果のまとめ：どう解釈するか

### 6.1 再現できたこと ✅

- **オラクルと静的モデルの差は大きく出た**（β=8 で +0.075）
- **greedy と静的はほぼ同じ** → sampling advantage は小さく、配分効果が主因
- **random mix は静的を下回る** → 「混ぜるだけ」ではダメで、系列ごとの選択が重要
- **フルモデルの絶対値は論文水準に到達**（0.312 vs 0.342）

つまり、論文の「**系列単位で深さを選べば得がある**」という定性傾向は、縮小版でも確認できました。

### 6.2 再現できなかったこと ⚠️

- **「層の 23% でフルと同等」には届かなかった**（47.9% まで）
- **c=4 が選ばれなかった**（11.4% vs 論文 69.6%）

原因は概ね **再現条件の差** にあります。

| 条件             | 論文                | 今回                           |
| ---------------- | ------------------- | ------------------------------ |
| 微調整           | フル微調整          | LoRA (r=16)                    |
| データ量         | Alpaca 全量 (7,800) | 2,000件（学習）／500件（評価） |
| エポック         | 6                   | 1                              |
| シード・信頼区間 | （論文は複数回）    | 1シード・なし                  |

絶対値の一致を期待する実験ではありません。**「傾向が出るか」を見る実験**として読むのが正しい姿勢です。

### 6.3 この結果の限界

1. **n=500・1シード・信頼区間なし**: 0.182 と 0.184 のような細かい差は誤差の範囲です。
2. **オラクルは出力のノイズも事後的に利用**: greedy との比較で小さいと分かりましたが、c ≤ β に限った比較です。**β=24 の greedy**（全4モデルの最良を選ぶ値）も見ないと、選択効果の上限は分かりません。
3. **プロンプトの扱いが簡易版**: 論文はプロンプトをフル層で処理し、生成トークンだけ層を飛ばします。今回は全体を層削除モデルで処理しています（KV キャッシュの扱いが面倒なため）。忠実版とはやや条件が違います。
4. **ルーターのコスト未計上**: プロンプト1回分の前向き計算がかかります。

## 7. まだ確認できていないこと・次のステップ

### 7.1 まず欲しい数字

- 微調整後の**静的 c=4 / c=12 の ROUGE-L**（c=4 仮説の検証）
- **β=24 の greedy** の値（選択効果の上限の把握）
- ルーターと random mix の**比較プロット**（実用化の見込み）

### 7.2 提案された次の実験（優先順）

1. **クロスラン・オラクル（推奨）**
   サンプリング生成を独立に2回行い、**1回目の結果で割当てを決め、2回目の結果で評価**します。ノイズへの事後的な当てはめが効かなくなるため、「プロンプト自体に難しさがある」ことをより直接検証できます。追加コストは4モデルの再生成数分程度（未実測）。
2. **信頼区間**
   ブートストラップで oracle・greedy・静的の差に信頼区間を付け、0.002 の差が有意かを判定します。
3. **c=4 の補強**
   エポック数や `n_train` を増やす、LoRA の rank を上げるなどして c=4 を立て直し、論文の選択比率に近づくかを見ます。

> まずは **1（クロスラン・オラクル）をノートブックに追記する**のが良い流れです。

## 8. 付録：用語集とファイル対応表

### 8.1 用語集（初心者向け）

| 用語                                   | やさしい説明                                                                          |
| -------------------------------------- | ------------------------------------------------------------------------------------- |
| **decoder-only Transformer**     | GPT 系のモデル。同じデコーダ層を積み、前のトークンから次のトークンを予測する          |
| **レイヤスキップ**               | 推論時に一部の層を通さず計算を削ること                                                |
| **ULS (Uniform Layer Skipping)** | 深さ方向に均等に層を残す方式。論文の式(2)                                             |
| **c / β**                       | `c` ＝実際に実行する层数、`β` ＝許される平均层数（予算）                         |
| **ROUGE-L**                      | 生成文と正解文の最長共通部分列で一致度を測る指標（大きいほど良い）                    |
| **オラクル**                     | テストスコアを見て最適に選ぶ仮想制御器。**上限値**であり実用不可                |
| **greedy oracle**                | 予算内で各プロンプトの最良を選ぶだけ。sampling advantage を含む                       |
| **random mix**                   | 同じ選択比率をランダムに割当てたもの。配分効果の対照実験                              |
| **多選択ナップサック**           | 各項目（プロンプト）に1つ選ぶ製品（深さ）があり、総コスト制約下で価値を最大化する問題 |
| **LoRA**                         | 重み行列に低ランクの adapter を足し、パラメータの一部だけを学習する手法               |
| **Ridge 回帰**                   | 正則化付きの線形回帰。ルーターがスコアを予測するために使用                            |
| **sampling advantage**           | 複数候補を見て後から良いものを選ぶことで生じる見かけの改善                            |
| **クロスラン**                   | 割当て決定用と評価用で生成を分け、ノイズの当てはめを防ぐ手法                          |
